# Batch / member / attendance end-to-end suite

Replays the admin pages' real API calls (batch create/edit/trash, contact + invoice,
roster, batch attendance, trash/restore/edit, cancel/undo, batch transfer) against the
real route files and checks the rows written. The operator-facing behaviour it pins
down is described in `docs/BATCH_ATTENDANCE_HANDOVER.md`.

```sh
sudo tests/batch-attendance/run.sh           # all scenarios
sudo tests/batch-attendance/run.sh ATT-      # scenarios whose id/title contains "ATT-"
sudo tests/batch-attendance/run.sh --keep    # keep the databases and code copy for debugging
```

Scenarios depend on earlier ones (the batch made in BATCH-02 is used by the member and
attendance scenarios), so a filter is only useful for whole groups after BATCH-02.

## Isolation

`run.sh` never touches the live tree or a live database:

- the code is copied to `/tmp/ccc-bflow-*`; only that copy's
  `classes/dbconnection.class.php` is replaced (generated by
  `make-test-dbconnection.php`) so every `connect()` maps to the run's databases;
- `ccc_database_test_bflow_<hex>` / `ccc_central_test_bflow_<hex>` are created from a
  schema-only dump of `ccc_database_test` / `ccc_central_test` (no rows copied; only the
  `module` and `action` catalogues are inserted) and seeded by `seed.php` with
  fictitious staff, settings, a category and packages (`fixture.php`);
- the application connects through a temporary MySQL account that can see only those
  two databases;
- PHP's built-in server and the client run inside `unshare -n` (no network), so mail,
  SMS, FCM and Zoom calls cannot leave the machine; `sendmail_path` is `/bin/true`;
- databases, account and copy are dropped on exit. Every PHP file here exits unless run
  from the CLI (the `tests/` folder is web-reachable).

## Reading the output

- `PASS` expected behaviour holds; `FAIL` a regression (exit status 1);
- `KNOWN` the scenario reproduces a documented defect (marker in `flow.php`);
- `FIXED` a known defect no longer reproduces: remove its marker (exit status 1 until
  then).

PHP errors written by the application during the run are printed at the end.
